# 작업 지시서: 백엔드 및 인프라

## 목표
모든 포지션이 기댈 수 있는 API와 실행 환경을 만들고, 배포 URL에서 서비스가 돌아가게 한다.

## 담당 파일
- `backend/app/main.py`, `api/`, `db.py`, `config.py`, `schemas.py`, `services/events.py`
- `backend/tests/`
- (만들 것) `Dockerfile`, `compose.yaml`, `.github/workflows/ci.yml`

## 현재 상태
FastAPI, SQLAlchemy, SQLite로 이벤트, 할 일, 음성 명령, 통계, 추천 API가 동작하고 테스트 15개가 통과합니다.

## 5일 작업
| 요일 | 작업 | 완료 기준 |
| --- | --- | --- |
| 월 | GitHub 저장소 생성, 브랜치 보호 설정, 전원 clone 후 `setup.bat`과 `run.bat` 실행 지원 | 5명 PC 모두 http://localhost:8000 동작 |
| 화 | `Dockerfile`과 `compose.yaml` (앱 + PostgreSQL), `.env`로 DB 전환 | `docker compose up` 한 번으로 실행 |
| 수 | GitHub Actions CI: PR마다 `pytest` 실행. AWS 계정 Budget 알림 설정 | PR에 테스트 결과 표시 |
| 목 | AWS 배포 (ECR + App Runner 또는 EC2), HTTPS 확인 | 배포 URL에서 카메라, 마이크 동작 |
| 금 | 배포 환경 안정화, 롤백 방법 정리, 시연 후 리소스 정리 계획 | 배포 URL로 시연 가능 |

## 협업 포인트
- 다른 포지션이 API를 요청하면 먼저 `docs/event-schema.md`에 형식을 적고 합의한 뒤 구현합니다.
- 통합 테스트(17시)를 진행하고 깨진 부분의 담당자를 지정합니다.

## 주의
- PostgreSQL 전환 시 `psycopg[binary]`를 requirements에 추가하고 `DATABASE_URL`만 바꿉니다.
- 테이블 구조가 바뀌면 지금은 `data/app.db`를 지우고 다시 만듭니다. 배포 후에는 Alembic 도입을 검토합니다.
- AWS 비용: 사용하지 않는 서비스는 바로 중지하고 Budget 알림을 먼저 설정합니다.
