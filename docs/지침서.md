# 개발 지침서

모든 팀원이 공통으로 지키는 규칙입니다. 바꾸고 싶으면 PR로 제안하고 팀 합의 후 수정합니다.

## 1. 원칙

1. **연결 먼저, 기능은 나중에.** 자기 기능이 완벽하지 않아도 매일 17시에는 전체 흐름에 붙어 있어야 합니다.
2. **계약을 지킨다.** 이벤트 형식과 API는 [event-schema.md](event-schema.md)가 기준입니다. 바꾸려면 먼저 문서를 고치는 PR을 올립니다.
3. **영상과 음성 원본은 저장하지도, 서버로 보내지도 않는다.** 인식 결과만 보냅니다.
4. **MVP 범위 밖은 하지 않는다.** LLM 대화, 아바타, ML 추천 모델은 2차입니다.

## 2. 환경

- Python 3.12 이상, Chrome 최신 버전
- 가상환경은 프로젝트 루트의 `.venv` 하나를 사용합니다 (`setup.bat`).
- 새 패키지를 추가하면 `requirements.txt`에 적고 PR 설명에 이유를 씁니다.
- 비밀값(API 키, DB 비밀번호)은 `.env`에만 둡니다. `.env`는 커밋하지 않고, 새 변수는 `.env.example`에 예시로 추가합니다.

## 3. Git 규칙

- `main`은 항상 실행되는 상태를 유지합니다. 직접 push 금지.
- 브랜치 이름: `feature/<포지션>-<기능>` 예: `feature/voice-todo-add`, `feature/vision-pointing`
- 버그 수정: `fix/<내용>`
- 커밋 메시지: `[포지션] 무엇을 했는지` 예: `[voice] 할 일 삭제 명령 추가`
  - 포지션 태그: `voice`, `vision`, `data`, `front`, `backend`, `infra`, `docs`
- PR은 작게, 하루 1개 이상 올립니다. 최소 1명 리뷰 후 병합합니다.
- PR 올리기 전: `pytest` 통과, 브라우저에서 http://localhost:8000 정상 동작 확인.

## 4. 코드 규칙

- Python: 함수 이름 `snake_case`, 타입 힌트 사용, 비즈니스 로직은 `services/`, 라우터는 `api/`.
- JavaScript: ES 모듈, `camelCase`, 서버 호출은 반드시 `js/api.js`를 거칩니다.
- 이벤트 저장은 백엔드에서 `services/events.py`의 `record_event()` 하나로만 합니다.
- 시간은 DB에 UTC로 저장하고, 화면과 분석에서만 한국 시간으로 바꿉니다.
- 자기 담당 파일이 아닌 곳을 고쳐야 하면 담당자에게 먼저 알립니다 (README의 담당표 참고).

## 6. 막혔을 때

30분 이상 막히면 혼자 붙잡지 말고 팀 채널에 공유합니다. 무엇을 시도했고 에러 메시지가 무엇인지 같이 적습니다.

## 7. AI 코딩 도구 사용 시

- 생성된 코드는 이해하고 나서 커밋합니다. 설명할 수 없는 코드는 PR에 올리지 않습니다.
- 이 지침서와 event-schema.md를 도구에 함께 제공해 규칙을 따르게 합니다.
