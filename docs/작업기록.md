## 기록

### 2026-10-16 #1 프로젝트 뼈대 만들기

**무엇을 했나**
- 포지션을 5개로 정했습니다: 음성 인식, 가리키기 모션, 데이터 엔지니어링, 프론트(대시보드), 백엔드 및 인프라.
- FastAPI와 SQLite로 백엔드를 만들었습니다. 이벤트 저장과 조회, 할 일, 음성 명령 처리, 시간대 통계, 추천 API가 있습니다.
- HTML과 JavaScript로 대시보드를 만들었고, 서버가 같은 주소에서 화면도 함께 보여 줍니다.
- 문서를 작성했습니다: README, 지침서, event-schema, 포지션별 지시서.

**왜 이렇게 했나**
- 5일 안에 끝내야 해서 "손동작에서 서버, DB, 화면까지" 한 줄이 먼저 돌아가는 것을 목표로 했습니다.
- 모든 행동을 `events` 테이블 하나에 쌓도록 했습니다. 포지션마다 테이블을 따로 만들면 합치는 작업이 늘어나고, 하나로 모아 두면 데이터 엔지니어링이 바로 분석할 수 있습니다.
- 영상과 음성 원본은 서버로 보내지 않습니다. 브라우저에서 인식한 결과만 보내면 비용과 개인정보 위험이 줄어듭니다.
- 프론트를 React 대신 HTML과 JavaScript로 만들었습니다. npm 설치와 빌드 과정 없이 `run.bat` 하나로 바로 실행됩니다.
- 처음에는 SQLite를 씁니다. 설치할 게 없어서 5명 모두 바로 시작할 수 있습니다.
- 추천은 머신러닝 대신 "최근 7일 중 4일 이상 같은 시간대" 같은 규칙으로 했습니다. 처음에는 데이터가 적어서 모델을 학습시켜도 의미가 없습니다.

**다른 방법은 없었나**
| 선택 | 다른 방법 | 지금 방법을 고른 이유 |
| --- | --- | --- |
| HTML + JavaScript | React + Vite | 빌드 도구가 필요 없음. 대신 화면이 커지면 코드 관리가 어려워짐 |
| SQLite | 처음부터 PostgreSQL + Docker | 설치 부담이 없음. 배포 직전에 `DATABASE_URL`만 바꾸면 됨 |
| 브라우저 Web Speech API | Whisper 같은 서버 음성 인식 | 무료이고 바로 쓸 수 있음. 대신 Chrome에 의존함 |
| 규칙 기반 명령 파서 | LLM으로 명령 해석 | 비용과 지연이 없고 테스트가 쉬움. 대신 표현이 다양해지면 규칙이 계속 늘어남 |
| 시작할 때 테이블 자동 생성 | Alembic 마이그레이션 | 연습 단계라 단순하게. 테이블 구조가 바뀌면 DB 파일을 지워야 함 |

**더 좋게 만들 방법 (추천)**
- 화면이 3개 이상으로 늘어나면 React로 바꾸는 것을 검토하세요. 지금 `js/` 모듈 구조를 그대로 컴포넌트로 옮기면 됩니다.
- 배포하기 전에 PostgreSQL과 Alembic을 함께 도입하세요. 실제 데이터가 쌓인 뒤에 DB 파일을 지울 수는 없습니다.
- 명령 파서가 처리하지 못한 문장은 `voice_command` 이벤트에 `intent: unknown`으로 남습니다. 이걸 모아 보면 어떤 규칙을 추가해야 할지 알 수 있습니다.
- 대시보드는 5초마다 서버에 새 데이터를 요청합니다(폴링). 이벤트가 많아지면 WebSocket으로 바꿔서 새 데이터가 생길 때만 받게 하세요.

### 2026-10-16 #2 포인팅 데모 (양손 관절, 집기 선택, 호출어)

**무엇을 했나**
- `pointer.html`을 새로 만들었습니다. 카메라 영상은 보여 주지 않고 손 관절만 그립니다.
- 왼쪽 패널에 양손 관절과 현재 손 모양(가리키기, 집기, 손바닥, 주먹)을 실시간으로 표시합니다.
- 검지만 펴면 커서가 움직이고, 엄지와 검지를 붙이면(집기) 커서 아래 카드를 선택합니다. 양손에 커서가 하나씩 따로 있습니다.
- "자비스"라고 부르면 활성화되어 8초 동안 명령을 듣습니다.
- 손 모양 판정은 `hands.js`, 호출어 처리는 `wake-word.js`로 나누었습니다.
- `voice.js`의 `speak()`가 말이 끝날 때 완료되는 Promise를 돌려주도록 고쳤습니다. 기존 코드는 그대로 동작합니다.

**왜 이렇게 했나**
- MediaPipe의 GestureRecognizer 대신 HandLandmarker를 썼습니다. 정해진 제스처 이름 대신 관절 21개의 좌표를 받아야 집기 같은 동작을 직접 판정할 수 있기 때문입니다.
- 선택 동작으로 집기를 골랐습니다. 가리킨 채 그대로 있으면 선택되는 방식(일정 시간 머무르기)은 원하지 않는 카드까지 선택되는 일이 잦습니다.
- 집는 순간 커서를 고정했습니다. 손가락을 오므리면 검지 끝이 움직여서 커서가 옆 카드로 넘어가기 때문입니다.
- 카메라 화면 가운데 70% 영역을 화면 전체로 늘렸습니다. 손을 크게 움직이지 않아도 화면 끝까지 닿게 하려는 것입니다.
- MediaPipe는 거울에 비친 이미지를 기준으로 왼손과 오른손을 구분합니다. 웹캠 원본은 거울 이미지가 아니라서 판정 결과를 서로 바꿨습니다.
- 비서가 말하는 동안에는 음성 인식 결과를 무시합니다. 그러지 않으면 스피커에서 나온 비서 목소리를 명령으로 알아듣습니다.

**다른 방법은 없었나**
| 선택 | 다른 방법 | 지금 방법을 고른 이유 |
| --- | --- | --- |
| 검지 끝 위치를 커서로 사용 | 손가락 방향으로 화면까지 직선을 그어 계산 | 노트북 웹캠은 깊이 정보가 부정확해서 직선 계산이 많이 흔들림 |
| 집기로 선택 | 일정 시간 머무르기, 주먹 쥐기 | 집기가 가장 의도가 분명하고, 주먹은 손 전체가 움직여 커서가 튐 |
| 브라우저 음성 인식으로 호출어 감지 | Porcupine 같은 전용 호출어 엔진 | 설치와 비용이 없음. 대신 계속 듣는 동안 음성이 구글 서버로 전송되고 인식률이 낮을 수 있음 |
| 손 모양을 규칙으로 판정 | 직접 모은 데이터로 분류 모델 학습 | 데이터 수집과 학습 없이 바로 동작함 |

**더 좋게 만들 방법 (추천)**
- 커서가 떨리면 지수 평활(`SMOOTHING`) 대신 One Euro Filter를 쓰세요. 손이 느리게 움직일 때는 떨림을 잡고, 빠르게 움직일 때는 지연이 줄어듭니다.
- 집기 판정 기준 하나만으로 켜고 끄면 경계에서 깜빡입니다. 켤 때와 끌 때 기준을 다르게 두세요(히스테리시스). 예를 들어 0.30 이하에서 집기가 시작되고 0.40 이상이 되어야 풀리게 합니다.
- 노트북 성능이 낮으면 손 인식을 매 프레임이 아니라 2프레임에 한 번만 돌리세요.
- 호출어 인식이 불안정하면 비슷하게 들리는 단어를 함께 등록하세요. 예: "자비스", "자비 스", "잡이스".
- 시연 전에 조명이 다른 장소 두 곳에서 집기 판정 값(`PINCH_RATIO`)을 맞춰 두세요.
- 손 관절 판정 테스트를 브라우저 없이 돌릴 수 있게 `hands.js` 단위 테스트를 추가하세요. 지금은 수동으로만 확인했습니다.
